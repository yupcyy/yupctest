## 迁移矩阵及目标结构草案

| 能力 | 当前落点 | 建议 |
| --- | --- | --- |
| 人格及回复语气 | prompt_manager、affinity | 保留人格，注入有长度上限的情绪快照 |
| 动态情绪 | 上游 emotion.py 有效价/唤醒度及时间衰减 | MIT 算法可适配；修正重叠关键词重复计分、否定句误判 |
| 好感度与画像 | AffinityService 已有分数、封禁、礼物 | 保持唯一分数源；不能引入上游 0..100 覆盖当前负分规则 |
| 群聊气氛 | 上游 atmosphere.py 有窗口统计 | 独立适配，使用短期内存窗口；不学习或长期保存群友聊天风格 |
| 长期记忆 | MemoryService、memory_sqlite | 扩展现有读取链，加入来源、可见范围、到期和去重 |
| 主动消息 | router、OneBot 发送链 | 统一一个决策和调度入口，避免两个插件各自触发 |
| 睡眠 | 已有用户晚安/早安需求 | 用户睡眠计时与 Agent 作息分开，保留一次覆盖语义 |
| 梦境和日记 | congling night、memory/diary | 独立实现，明确虚构梦境，禁止反写为真实用户事实 |
| 主动社交 | 现有 QQ 通道 | 默认关闭，仅许可对象，发送前再次检查权限和免打扰 |
| 配置管理 | FastAPI 和现有 WebUI | 接入现有主人认证，避免另开无认证管理服务 |

拟新增独立 companion 服务层：事件归一化 → 情绪/画像/气氛快照 → 主动决策 → 现有发送器。所有主动发送共用目标白名单、每目标冷却、每日限额、时区明确的免打扰、全局停用和去重键；关闭开关后取消已排队任务。情绪不得改变管理员身份、工具授权或解禁状态。

私聊记忆默认不进入群聊模型上下文。允许影响群聊的内容仅限经过显式发布策略提炼的非敏感偏好；不能只依靠提示词保证不泄露。

## 用户追加要求与封禁专项审计

用户要求：放宽封禁；保留负好感度；允许用两个上游的关系功能优化或覆盖当前规则。以下方案覆盖上文中保守沿用旧封禁逻辑的部分，仍受上游许可约束。

当前 `core/router.py` 存在三个明确的自动永久暂停入口：攻击后分数 <= -40、强迫措辞后分数 <= -40，以及分数 <= -20 时 60 秒内第 4 次调用。暂停检查发生在礼物/安慰处理之前，因此暂停后不能通过正常互动修复。`services/affinity.py` 单次攻击扣 30、强迫扣 15；“你必须”“不然”等宽泛匹配容易误伤普通请求。这些是放宽的主要目标。

拟采用以下行为（待第二阶段实现）：

- 负好感度本身不触发封禁；普通频繁互动不扣分，短时过载仅返回冷却提醒，自动恢复。
- 普通命令式措辞不视作恶意；明确威胁才小幅扣分。敏感信息套取和越权工具请求仍拒绝该次操作，但不因一次请求永久暂停用户。
- 自动保护采用短时冷却和逐步退避；永久封禁仅由主人命令设置。管理员手动封禁与自动冷却分离，前者不能通过送礼绕过。
- 礼物、安慰可用于修复负好感；保留每天三次礼物和服务端单次增量限制。自动冷却期间也限制处理频率，不能利用安慰刷分或绕过安全拒绝。
- 好感度保持全局 QQ 绑定的 -100..100 唯一数据源。情绪为会话短时状态，关系为长期分数；生气不等于权限降低，亲近不等于授予额外权限。
- 关系阶段覆盖负分到正分；低分疏离、简短，中高分更愿意延伸话题。负面情绪不辱骂、不施压索取陪伴。普通聊天默认仍可使用授权工具，移除旧版高概率随机拒绝工具造成的不确定体验，若有可选情绪化拒绝，仅用于非必要娱乐请求。

上游对照证据：companion `core/affection.py` 将关系与情绪分开，但分数限于 0..100，不能直接替代负分存储；`core/emotion.py` 提供向基线衰减模型。congling `memory/affinity.py:add` 有每日自动变化额度、证据关联和阶段下限，但阶段下限阻止掉分、0 下限与本项目要求冲突，应独立设计双向阶段和每日累计绝对变化额度，不能直接移植。不能使用净变化额度，否则正负抵消可绕过限制。

主动行为审查：companion `main.py:_maybe_proactive` 在生成前检查会话开关、发送熔断、私群白名单、免打扰、日额度、闲置时间、气氛和冷却；发送成功后才计数。congling `humanize/proactive.py:should` 增加作息、精力、全局及会话额度、未回复次数门控。目标实现合并这些门控；配额预留、并发锁、发送前二次检查及失败恢复仍需专门验证，不能只照搬生成前判断。

记忆审查：当前 `MemoryService.context_for` 明确禁止私聊记忆进入群聊，并只在私聊注入主人风格。延续该默认；群聊气氛只使用有界短期窗口，不作为长期学习样本。

数据库影响：先实现不需要新表的关系提示与判定纯函数、模拟存储测试；持久化冷却/人工封禁类型须先审查现有 guard 字段，再提供明确迁移方案。未经批准不清除现有封禁、不改现有分数、不读取实际数据库。旧暂停记录不能在无法区分来源时自动全部解除。

待审计：全量记忆检索/遗忘、夜间模块、WebUI 认证、完整调度生命周期与测试副作用。第一阶段仍未完成；上述为已读源码的专项结果。
