# 拟人陪伴功能

启用需要现有 SQLite 已执行 `scripts/database/companion_schema.sql`，并设置 `ENABLE_COMPANION=true`、`COMPANION_PERSISTENCE=true`。默认关闭，不自动建表。

主人私聊指令：

- `/画像 内容`：保存主人提供的画像；`/画像` 查看。仅在主人私聊作为资料注入，群聊不注入。
- `/日记 生成`、`/梦境 生成`：通过现有无工具通道生成，每类每小时最多一次。裸指令查看记录。梦境显式标记为虚构，不反写为用户事实。
- `/拟人 停止`、`/拟人 恢复`：控制拟人主动行为；`/拟人 睡觉`、`/拟人 醒来` 控制 Agent 作息。此状态与用户晚安/早安计时分开。
- 原有 `/主动` 控制仍生效。

主人通过原有 `/oalogin` 登录后访问 `/companion`，查看状态、画像和日记。页面只读，管理通过 QQ 主人身份完成。

存储只新增 `agent_companion_state` 和 `agent_companion_journal`。后者每主人保留最近60条，查询最多30条。群聊气氛只保留十分钟统计，不保留聊天文字。亲密度保留 -100..100，不授予工具或管理权限。

已验证：19项定向测试通过。尚缺：自动夜间梦境与日记调度、统一主动额度及未回应退避、完整上游源码审计、真实 OneBot 联调、WebUI端到端验证与性能评估。当前不能视为计划全部验收。新功能开关尚未修改生产配置。

后续进展：加入共享主动预算（每日全局6次、每群2次、私聊3次），09:00–23:00北京时间可主动发言，连续两次未回应暂停，目标回应后重置未回应计数。预算预留在生成前，生成/发送失败仍消耗额度，以避免重试风暴。当前预算在内存中，重启会重置；原有数据库冷却继续生效。

`COMPANION_AUTO_JOURNAL=true` 可开启静默归档：配置时区22点写心情日记，4点且Agent处于睡眠状态时生成虚构梦境。共享现有小时调度，无额外后台线程；同一天预留一次，失败不自动重试。此功能不会向QQ主动发送归档内容。主人紧急停止时跳过夜间归档。夜间生成尚未做真实模型联调。

主人主动文案生成后会再次检查停止、睡眠和主动关闭设置。尚缺：预算跨重启持久化、群聊消息在适配器发送前的二次检查、发送结果统一记账、完整上游审计、WebUI端到端和性能评估。新增调度独立测试仍需补齐，不能据此宣布全计划完成。

### 成员画像

画像依赖现有陪伴持久化存储（`ENABLE_COMPANION=true`、`COMPANION_PERSISTENCE=true`，且已有所需表）；本功能不自动创建表。所有画像命令仅私聊可用：

- 主人 `/画像 QQ号` 查看指定用户画像。
- 主人 `/画像 QQ号 补充 内容` 追加资料，省略“补充”也可追加。
- 主人 `/画像 QQ号 设置 内容` 替换资料。
- `/画像` 查看本人画像；`/画像 内容` 补充本人画像。

`ENABLE_SELF_PROFILE=false` 为默认值，普通用户不能自行设置或通过此入口查看画像；主人始终可管理。开启后，普通用户只能操作自己的画像。画像总长最多 500 字，记录最近修改者，标记 `scope=group`。群聊回复对应 QQ 用户时注入；本人私聊也可了解群聊画像，但明确标注其场景，并提示私聊画像尚未建立。不改变权限、不主动复述画像。旧无 scope 的画像按群聊画像兼容读取，不自动改写数据库。画像管理仍仅私聊可用。

模型每次请求都会从系统时钟刷新 Asia/Shanghai 中国时间（UTC+08:00），不依赖会话历史记时；不修改主机时区或操作系统的时间同步服务。

群聊画像查询支持 `@机器人 @目标用户 介绍一下`，以及 `@机器人 用户123456怎么样` 等带明确 QQ 号的问题；最多读取五个目标的群聊画像。没有群聊画像时明确提示缺失。昵称不能唯一定位时要求 @目标或提供 QQ 号，不使用私聊画像或私有记忆推断。被 @用户 ID 作为一次性结构化上下文传递，不拼入发言者原话历史。

工具路径按本请求实际授权的函数工具生成能力说明，MCP 工具以实际工具定义为准；无工具路径明确说明无法调用工具。系统时间每次请求自动注入，模型可以直接回答中国时间，但不能据此声称拥有修改主机时钟或网络校时权限。
